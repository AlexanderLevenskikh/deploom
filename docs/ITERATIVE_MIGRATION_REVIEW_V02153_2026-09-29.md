# Повторная приёмка v0.2.153

Проверен чистый HEAD `089c702`. Основное и дополнительное задания продвинулись: старые R1/R2/R4/R8 исправлены на уровне отдельных переходов, Node selector и семантика engines работают на тестовых границах. Целевой пользовательский сценарий пока не принимается. Проверка проведена без запуска реального приватного проекта и без публикации.

## Блокирующие замечания

1. **Нет непрерывной миграции из Desktop.** `desktop/src/components/IterativeTaskPanel.tsx` показывает «Выполнить следующий шаг» и вызывает `onStep` ровно один раз; `main.ts` handler `flow:iterative:step` исполняет одну CLI-команду и возвращается. Агент запускается отдельным кликом. Обычный Flow/Autopilot по-прежнему ведёт через Baseline. Требование «C0→группа→агент→проверка→следующая группа без ручных внутренних шагов» не выполнено. Нужен durable supervisor, который продолжает после каждого шага, останавливается на user/agent gate и сохраняет управление при перезапуске.

2. **Первый полезный upgrade всё ещё зависит от старого roadmap.** `desktop/electron/main.ts` в `flow:iterative:begin` получает targets исключительно из `.dependency-roadmap/state/dashboard-state.json` через `targetsFromDashboardState`; если файла нет, в begin передаётся пустая карта. `iterative_migration.py::_plan_next_locked` при пустых targets завершает NO_ACTIONABLE. Для реального проекта, где старый Baseline не смог закончить поиск, новый путь не выбирает даже первую группу. Нужен самостоятельный bounded target discovery по registry/lag policy от C0, без полного yellow→green→default и без выдумывания версии; bootstrap может использовать уже сохранённый roadmap, когда он есть.

3. **Переэкспорт stale task снова отключён.** В `IterativeTaskPanel.tsx` кнопка «Переэкспортировать» имеет `disabled={busy !== undefined || snapshot?.stale}`. После C1 task C0 закономерно stale, а сама панель просит переэкспортировать перед агентом. Нет task — нет экспортной кнопки вообще. В результате следующий repair может упереться в TASK_STALE. Разрешить export при missing/stale/failed; stale запрещает только dispatch старого scope.

4. **Запрещённые правки агента не обнаруживаются.** `desktop/electron/iterative-agent.ts` `writeTrialBaseline` и `changedFilesFromBaseline` вызывают `skipEntry` для package.json/lock/других forbidden names; удаления исходных файлов тоже игнорируются. `main.ts` передаёт Python лишь этот неполный список плюс текстовый CHANGED_FILES агента. Тест `check-iterative-agent.mjs` прямо ожидает, что package.json НЕ будет в diff, поэтому зелёный тест закрепляет пропуск. Агент может изменить или удалить manifest/lock, а контроллер не заметит это как нарушение ownership перед READY_FOR_VERIFY. Хешировать все значимые файлы, отдельно классифицировать forbidden/removed и отклонять такую попытку до feedback/verification; текст агента не источник истины.

5. **Lease предотвращает повтор, но не восстанавливает агентскую сессию.** `main.ts:flow:iterative:agent` при живом `agent-lease.json` возвращает AGENT_IN_PROGRESS; сохранённый `sessionId` далее нигде не используется для resume (`buildOpenCodeAgentArgs(..., undefined, ...)`). После рестарта UI может ждать до истечения двух часов, затем новая сессия создаётся для того же attempt. Нужен реальный resume того же provider session/transport либо явная детерминированная процедура завершения умершего процесса с сохранением trial edits и бюджта. Проверять kill посреди работы последней попытки, а не только round-trip JSON lease.

6. **Node выбирается для исполнения, но не для поиска новых версий в iterative planner.** `iterative_migration.py::_plan_next_locked` использует готовый `config.targets` и `plan_progressive_extension`; до materialize он не запрашивает metadata engines.node для этих targets и не выбирает совместимую альтернативу. Engine guard добавлен в legacy generator, который производит dashboard-state. Поэтому CI Node 20.11.0 + target с engines `^22.18.0 || >=24.11.0` в новом пути выясняется на install, когда старый roadmap уже передал несовместимый target. Нужно применить runtime-aware candidate selection к bounded iterative planner и дать альтернативу/отложенную цель до дорогой материализации. Транзитивная несовместимость остаётся подтверждаемой install evidence.

7. **Старая кнопка «Скопировать промпт» не исправлена.** `desktop/src/components/PromptPreviewDialog.tsx` и dashboard `copyPrompt` по-прежнему используют navigator.clipboard; новый Electron clipboard применяется только к iterative task. Дополнительное задание требовало проверить и этот ранее сообщённый путь через реальное нажатие. Нужна проверка UI→preload→IPC→clipboard для старого и нового preview и понятный fallback.

## Подтверждённый прогресс и пределы доказательств

- Кодовый переход MATERIALIZED→precheck появился; VERIFYING теперь допускается в Python. Begin и аудит перед finish добавлены.
- `node_range_satisfied('^22.18.0 || >=24.11.0', version)` даёт false для 20.11.0, 22.17.0, 24.10.0 и true для 22.18.0, 24.11.0.
- Проверены локально: `test_iterative_runtime_request.py` — 14 OK; `test_iterative_migration_schemas.py` — OK; Desktop `check:iterative-runner`, `check:iterative-agent` — OK. Эти тесты не проверяют непрерывный Desktop цикл, настоящий provider resume и выбранный Node при физическом install/CI.
- `docs/ITERATIVE_MIGRATION_ACCEPTANCE.md` в HEAD до сих пор описывает старые 1446 Python тестов и открытый agent handoff; новая реализация v0.2.153 в нём не принята. Статус реализации сам указывает, что real-agent pilot и реальная установка под выбранным Node не выполнены. Зелёная сборка и релиз v0.2.153 не заменяют эти границы.

## Критерий следующей сдачи

Один Desktop integration/physical сценарий: пустой workspace и Node 20.11.0 → bounded discovery первой совместимой группы → exact install под выбранным Node → agent repair выбранным provider → C1 → C2 → альтернативная/отложенная группа → partial/complete с audit. Без ручного внутреннего шага или dashboard. Отдельно kill во время agent/verify/acceptance, stale task regeneration, forbidden mutation и старый clipboard UI. Для реального пилота использовать изолированную копию согласованного проекта с ограниченным бюджетом; если условия отсутствуют, честно фиксировать BLOCKED.
