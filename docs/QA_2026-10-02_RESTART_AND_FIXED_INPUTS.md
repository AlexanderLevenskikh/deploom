# Проверка перезапуска и восстановления миграции — 2026-10-02

Проверена рабочая копия на базе `6d3dae0` (v0.2.165). Изменения этой приёмки не опубликованы; установленное приложение автоматически их не получит.

## Что исправлено

- Старый журнал `running` без `run.json` больше не предлагает `drive`: интерфейс предлагает повторить предварительную проверку. Для существующего прогона продолжение сохраняется.
- В основной карточке появилась отдельная кнопка «Начать заново». Она запускает Python `archive-run`, сохраняет состояние целиком в `run-archive/<id>/`, затем проверяет текущие файлы проекта. Исходный Git checkout, изменения пользователя и прежние checkpoints не удаляются.
- Незавершённый перенос восстанавливается из транзакционного журнала; подтверждённый перенос не откатывает новый прогон. Ошибка перемещения возвращает прежние файлы. Живой владелец run lock не теряет блокировку из-за возраста; незакрытая сессия агента запрещает новый запуск.
- Git/file/workspace/alias зависимости остаются в исходном manifest и proof identity, но исключаются из назначения управляемых версий. Их установка и команды проекта проверяются. Попытка заменить fixed input и смешанные registry/fixed объявления по-прежнему запрещены.
- Ошибка прежнего плана извлекается из stdout Python, поэтому вместо одного `LEGACY_EXPORT_EXIT_2` видна причина и следующий шаг. Если для выбранного проекта нет сохранённого плана, кнопка не предлагается.
- Остановка preliminary check записывает `canceled`, а не ошибку с сырым progress event. Остановка drive сохраняет checkpoint; интерфейс не показывает её как аварийную ошибку. Счётчик времени завершённых и прерванных попыток заморожен.
- Кнопка в технических деталях явно названа «Перезапустить старый Baseline (чистый Git)»: это отдельный старый маршрут, а не новый итеративный перезапуск. Требование чистого checkout у старого маршрута не отключалось.
