# Воспроизводимые сценарии проектов

Набор демонстрирует поведение производственных функций DepLoom на специально созданных проектах. Он не запускает миграцию пользовательского репозитория. Каждый запуск создаёт отдельный каталог с исходниками, `evidence.json` каждого сценария, итоговым `results.json` и `REPORT.md`.

```powershell
python scripts/run-real-world-demos.py --list
python scripts/run-real-world-demos.py
python scripts/run-real-world-demos.py --core-only
python scripts/run-real-world-demos.py --case physical-child
```

По умолчанию артефакты сохраняются в `.dependency-roadmap/demos/real-world/<unique-run>/`. `--output-dir` меняет родительский каталог, но каждый прогон получает новый каталог. Повторный запуск не перезаписывает предыдущие результаты.

## Покрытие

| Группа | Проверяемое поведение |
| --- | --- |
| Монорепозитории npm, Yarn Classic и modern Yarn | Выбор корневого либо вложенного `package.json`, владение lock-файлом, неизменность соседнего пакета. |
| Workspaces | Массив, объект `packages`, brace pattern; отдельный lock-файл вложенного проекта. |
| Форматы JSON | Minified, BOM, CRLF, Unicode, дополнительные поля; невалидный JSON отклоняется без записи. |
| Registry selectors | Exact, caret, tilde, range, latest и разные секции dependencies/dev/optional/peer. |
| Fixed inputs | workspace/file/link/npm alias/Git не превращаются в registry assignment. |
| Неоднозначность и неподдерживаемые варианты | Несколько найденных проектов, конфликт lock-файлов, не принадлежащий workspace, PnP и pnpm — проверяется ожидаемый отказ, а не заявляется поддержка. |
| Наблюдение установленных версий | Hoisting, local package, затеняющая неправильная версия, отсутствующий пакет. |
| Продолжение | Возобновление завершённого прогона с сохранённой контрольной точкой и бюджетами. |
| Физическая установка npm | Реальные установки в монорепозитории: меняется выбранный корень либо child, sibling сохраняется. Отдельно — resolver PASS с последующим lifecycle FAIL. |

Всего 40 сценариев: 37 контрактов файловой системы и три физических сценария npm. Физические сценарии используют настоящий npm и Node, tarball-пакеты из локального HTTP registry на `127.0.0.1` и отдельный cache. Публичный registry и токены не нужны. PASS такого сценария означает, что ожидаемое поведение подтверждено; lifecycle FAIL является ожидаемым исходом соответствующего негативного сценария и не означает успешную миграцию проекта.

Yarn-сценарии этой демонстрации проверяют топологию и изменение манифеста. Физические установки здесь проверяются для npm; существующие acceptance-тесты Yarn остаются отдельным подтверждением установки Yarn. Не следует читать успешный тест выбора lock-файла как доказательство сборки и тестов проекта.

Набор собирается каноническим тестовым runner через `tests/regression/test_real_world_workspace_demos.py` и отдельно запускается в Linux/Windows CI. При отладке сохранённые проекты и доказательства доступны в каталоге прогона; создавайте новый прогон, чтобы сохранить исходный результат.
