# Повторный аудит и исправления DepLoom 0.2.181

Проверена исходная ревизия `8ca39d5559d9b463e16833681dcb05423e5cdc5e`.
Исправления находятся в рабочем дереве поверх неё; новый релиз не публиковался.
Датированные прежние отчёты не использовались как доказательство исправности.

## Результат повторной проверки

Ранее описанные ограничения повторов установки, отдельный бюджет ремонта кандидата,
исключение C0 из принятых обновлений и валидация feedback до записи действительно
появились. Старые резервные `.bak` файлы удалены, документация получила индекс.
Физические профили используют реальные production Node-модули, Python CLI, Git,
npm, изолированные исходники и авторитетную проверку. Внешний платный агент в демо
заменён сценарными предложениями ремонта; это не проверка качества LLM.

Однако закрытие прежних замечаний было неполным:

| --- | --- | --- |
| P1 | UNKNOWN/infrastructure в `verify-exact` оставлял VERIFYING и exit 0: Node снова запускал ту же проверку без предела. | Сохранённый счётчик инфраструктурных повторов кандидата, остановка с причиной, сохранением C0/последнего checkpoint и repaired trial. ## Новые воспроизводимые сценарии

`tests/regression/test_iterative_reacceptance.py` проверяет совместную пару по разные
стороны разбиения, посторонний/version-neutral checkpoint и инфраструктурную
остановку проверки с сохранением trial, бюджета ремонта и восстановлением после
сбоя записи состояния. Файловый контроллер настоящий; внешняя верификация в этих
узких регрессиях подменена явно. Поэтому добавлен отдельный физический профиль:

```powershell
python scripts/run-iterative-demo.py --profile cross-group-companions --keep-output
```

Четыре настоящих npm-пакета: `is-finite` и `is-symbol` должны обновиться вместе,
находятся в разных половинах, по одному RED. Две шумные цели всегда RED по правилам
fixture. Production-планировщик нашёл и принял совместную пару. Итог:
`PARTIAL_VERIFIED`, одна принятая когорта, оба компаньона обновлены, две шумные цели
остались на исходных версиях. Правила fixture не выдаются за breaking changes этих
публичных библиотек. Driver не отправляет INCONCLUSIVE и не исправляет durable state
за программу. Сценарный агент отправляет только READY_FOR_VERIFY; отказ закрывает
авторитетная проверка.

## Оставшиеся ограничения и следующий порядок работ

1. Greedy + ограниченная рекомбинация — эвристика, не доказательство UNSAT. На больших
   группах возможны непроверенные сочетания. Следующее улучшение: целевые peer metadata
   и явный feedback компаньонов, чтобы реже тратить дорогие install/check на догадки.
2. Вариант companion без подсказок намеренно проверяет много отвергнутых кандидатов.
   Его успех не означает оптимальную длительность; cold/hot cache, число проверок и
   стоимость ремонта нужно измерять отдельно на реальных проектах.
3. Node demo использует production invocation/decision/stream/journal модули, но
   headless drive-loop и Electron IPC-loop всё ещё имеют отдельную обвязку. Выделение
   общего исполняемого coordinator сократит возможность расхождения. Полный Electron
   E2E и настоящий агент в этой приёмке не запускались.
4. Синхронная запись накопительного журнала остаётся: память теперь ограничена, но
   медленный диск может задерживать обработку. Следующий шаг — пакетная запись с
   backpressure и явным flush на stop/close, без потери событий и диагностики.
5. Ограниченный GC защищает активные и неизвестные trial. Это не универсальная очистка
   legacy-каталогов и пакетного кэша; квоты, pins, preview и файловые lease требуют
   отдельной политики. Пользовательское хранилище при этой проверке не очищалось.
6. Публикация частичного результата в исходный checkout и маркеры когорт в Git/MR
   остаются отдельным контрактом. Private checkpoint не означает изменения основной
   ветки. Не добавлен режим множества автоматически пушимых веток.

Пользовательские проекты и их текущие миграции не изменялись. Реальные демо доказывают
их собственные сценарии, а не успешную миграцию произвольного большого проекта.
