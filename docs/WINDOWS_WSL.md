# Проекты WSL в Windows-версии DepLoom

Windows-версия может подключать исходники через `\\wsl.localhost\Ubuntu\home\user\project` или `\\wsl$\Ubuntu\home\user\project`. Git, Python 3, Node.js, пакетный менеджер и выбранный агент должны быть установлены в **Windows**. Команды и сетевые запросы выполняются в Windows; Linux-версия DepLoom и установка этих инструментов в Ubuntu для этого режима не нужны.

## Подключение

1. Создайте workspace DepLoom на локальном диске Windows.
2. В «Добавить проект» выберите корень Git-репозитория в WSL.
3. В рабочей директории выберите папку с нужным `package.json`: корень либо конкретный подпроект.
4. Добавьте проект и запускайте обычный процесс обновления.

Если демка лежит в папке с отчётами и вспомогательными файлами, указывайте её подпапку `project`, содержащую `.git` и `package.json`.

## Как выполняются команды

Для выбранных WSL-репозиториев DepLoom передаёт точные `safe.directory` через окружение дочерних процессов, включая Python и агента. Глобальный Git-конфиг не изменяется. При следующем запуске приложения список восстанавливается из подключённых проектов. Остальные ошибки Git показываются с исходной диагностикой.

Для команд `.cmd` / `.bat` и явного `cmd.exe /c` в UNC-директории временный Windows-скрипт выполняет `pushd`, запускает исходную команду, сохраняет код завершения и выполняет `popd`. Это предотвращает выполнение команды из `C:\Windows` вместо выбранного проекта. Временная буква диска действует во время команды; проверки миграции продолжают использовать исходную идентичность проекта и отдельные рабочие копии.

Это режим Windows-инструментов: проектные команды должны работать в Windows. Если проект требует Linux-инструментов или Linux-окружения, используйте [Linux AppImage в WSLg](WSL_APPIMAGE.md).
