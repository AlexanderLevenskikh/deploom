# Selected goals, independent audit and semantic Git delivery

Desktop captures the saved “Configure scope / Draft” intent when beginning an iterative run. `keep-current` packages are excluded from discovery and protected during acceptance; they remain in the audit denominator. `required` packages must reach their captured exact target. Automatic version proposals are counted separately from success: a fresh passing independent audit and all required exact versions establish the selected policy. Legacy CLI runs without `--intent-file` retain their exact-target contract.

Audit thresholds and package lag overrides are frozen in the run identity. Editing the Draft after beginning changes the next run, not evidence for the active one. The initial selection audit caches unchanged dependency/policy/runtime input for up to 24 hours. C0 is independently audited before planning. A new checkpoint never borrows C0 metrics as current evidence. Missing, incomplete, stale and failed collection stay unconfirmed; no missing severity is converted to zero. Full auditing every cohort is deliberately avoided. The exact final state and the delivered branch are audited again.

The upper summary shows Critical/High limits, lag percentage with denominator and unknown coverage, required versions, frozen packages, initial comparison and evidence. Project rail health reads the latest authoritative audit rather than stale legacy roadmap labels. Artifact and iteration directory links are adjacent. The result branch and semantic commits have a separate result card; a clean Git tree does not establish fulfilled audit goals.

After the iteration loop, the agent has a bounded opportunity to repair residual audit goals in an isolated copy of the last verified checkpoint. It can address vulnerable transitive dependencies through their parents or justified package-manager overrides. Direct dependency scope, frozen versions, scripts, registry settings, the original input and source scope are guarded. Fresh configured verification and a nonregressing independent audit must precede checkpoint adoption. Unavailable audit evidence blocks repair. Failed repairs preserve the previous checkpoint and remain visible.

Delivery creates a registered Git worktree in the original project repository on the configured branch. An existing branch is reused only when it is exactly at the captured base commit and is not checked out anywhere. Otherwise the existing branch is preserved and a deterministic suffixed result branch is selected automatically; both requested and actual names are shown in the result card. Ref namespace collisions and subsequent runs choose another available suffix. The original checkout stays on its branch and is not pushed. Registered result worktrees have stable paths beside active runs, so “Start over” archives run evidence without moving or breaking a result worktree. An in-flight final agent session blocks archival until resumed/closed. Existing branches and unrelated changes are preserved. Meaningful ignored source/config inputs stop delivery before worktree creation: the controller neither silently drops those verification inputs nor automatically copies potentially sensitive hidden payloads. The verified checkpoint remains available. The agent groups related upgrades into semantic commits, keeps mutually dependent cohorts together and separates coherent substantial adaptations when useful. Prepared final source/manifest/lockfile bytes must remain unchanged. The agent authors or improves the two migration documents; their delivered hashes are recorded separately. Migration reports are included under `docs/dependency-migration/<run-id>/`.

Final verification checks a private clone of the exact delivered commit with the delivered working bytes (including Git checkout line-ending effects). This preserves the source guard that rejects absolute Git indirection in linked worktrees. The configured checks and independent audit run before recording delivery. A new advisory can downgrade a previous complete verdict. Audit failure is an honest partial result, even when commits are prepared.

Agent sessions and process IDs are saved before completion. A finished agent is not replayed after an audit/verification interruption; only verification resumes. Interrupted worktree copying resumes when files match the recorded base or intended snapshot. Unexpected edits stop recovery without overwriting them. Snapshot acceptance has a durable pending record, so recovery completes the same checkpoint adoption. No migration or provider call is required for UI fixtures and tests.

Browser QA: serve `desktop/monitor-harness.html` with Vite, then run `node scripts/qa-iterative-audit.cjs` from Desktop with Playwright available (or `DEPLOOM_PLAYWRIGHT_MODULE` pointing to its installed package). `DEPLOOM_QA_URL`, `DEPLOOM_QA_BROWSER_CHANNEL` and `DEPLOOM_QA_OUTPUT` optionally override the fixture URL, browser and screenshot directory. The fixture covers initial Critical, unknown evidence, final goals/commits, RU/EN, adjacent directory buttons, dark/light rendering and narrow windows.

Validation: `python -m unittest discover -s tests/regression -p test_iterative_delivery.py -v`, `npm run build`, `npm run check:iterative-delivery`, existing iterative/repair/Desktop contracts and `python run_tool_tests.py --suite all`. The Git boundary fixture uses real worktrees and Node checks; advisory evidence is deterministic test data, not evidence about a user's project.
