# Документы миграции

Язык документов задаётся явным выбором языка Desktop при запуске либо `--lang en|ru` в `iterative_migration.py begin`. Без выбора используется `en`; локаль ОС, браузера и Git не участвует. Значение сохраняется в `run-config.json` как `documentLanguage` и действует на весь набор документов этого прогона. Переключение языка интерфейса после запуска не меняет язык сохранённого прогона.

## Состав и расположение

| Артефакт | Содержание |
| --- | --- |
| `MIGRATION_REPORT.md` | Фактические изменения, контрольные точки, проверки, ограничения, аудит и объяснения адаптаций. |
| `DEVELOPER_UPGRADE_GUIDE.md` | Принятые обновления, сведения о возможностях и несовместимых изменениях, рекомендации разработчику. Незаписанные сведения явно обозначаются. |
| `pre-fix-audit-report.md` | Исходное состояние C0: метаданные, уязвимости, lag, инвентарь lock-файла и сверка доказательств. |
| `post-fix-audit-report.md` | Те же разделы для активной контрольной точки. |

Во время прогона файлы находятся в `<run-dir>/reports/`. Доставка переносит их в `docs/dependency-migration/<run-id>/` изолированной ветки проекта. Для `ru` все четыре Markdown-файла находятся в подкаталоге `ru/`; для `en` — непосредственно в каталоге прогона. Имена файлов одинаковы. `pre-fix-audit-report.json` и `post-fix-audit-report.json` находятся в корне каталога документов, не локализуются и содержат исходные данные аудита; при отсутствии аудита — явное состояние `UNKNOWN`. `documentation-evidence.json` содержит входные артефакты генерации и также не локализуется.

Предварительный отчёт создаётся после сохранения C0 и обновляется при аудите C0. Отсутствие аудита не прерывает прогон и не означает ноль уязвимостей. Завершение прогона создаёт весь набор. При подготовке доставки отсутствующие документы создаются, а существующие документы разработчика сохраняются для последующего дополнения агентом. Аудит-документы и JSON обновляются по фактическому C0 и активной контрольной точке, чтобы не копировать отчёт от предыдущего состояния. Агент может редактировать только два документа разработчика выбранного языка; аудит-документы и JSON входят в контроль целостности доставки.

## Доказательства и неизвестные данные

Каталоги переводов находятся в `document_locales/en.json` и `document_locales/ru.json`. Все заголовки и шаблоны общего генератора берутся из них; отсутствующие ключи или несовпадающие параметры шаблонов приводят к понятной ошибке до записи документов. Названия пакетов, версии, пути, команды, хеши, C0…C6, статусы, поля манифеста и исходные значения JSON не переводятся. Исходный JSON выделяется как отдельный блок доказательств.

Русская пометка отсутствующих данных:

> ⚠️ Данные недоступны: `<поле>`. Причина: <почему>. Как получить: <команда или шаг>.

Таблицы используют `N/A (не зафиксировано)`; каждый документ заканчивается разделом «Чего не хватает». В английской версии используются соответствующие английские шаблоны. Возможности новых версий и breaking changes не выводятся из одного номера версии: нужны записанные объяснения и источники.

Генератор проверяет хеш фактического манифеста sealed source против `manifestHash`, хеш lock-файла против `lockfileHash`, количество деклараций и `dependencyInputHash` аудита. После доставки проверяется манифест точного сохранённого Git-коммита. Расхождение помечается `UNVERIFIED`. Записанные цели не выдаются за установленные версии. При неполном аудите численные итоги не трактуются как доказанные. Сводка аудита контрольной точки сохраняется отдельно от полного JSON аудита; отсутствие последнего явно обозначается.

Документы описывают доказательства; их генерация не изменяет политику приёмки, вычисление lag или логику аудита. Реконструкция не создаёт отсутствующую верификацию.

## Повторная генерация и реконструкция

Повторно собрать документы существующего прогона:

```powershell
python migration_documents.py --run-dir <run-dir> --lang ru
```

Явный `--lang` применяется к этому вызову генератора. Без него используется язык сохранённого прогона. `iterative_migration.py finish --run-dir <run-dir> --lang ru` также сохраняет выбор для прогона; смена языка после начала доставки блокируется, чтобы не нарушить её закреплённые пути.

Собрать документы по двум манифестам и lock-файлам:

```powershell
python migration_documents.py --before-manifest <before/package.json> --after-manifest <after/package.json> --before-lock <before/yarn.lock> --after-lock <after/yarn.lock> --lang ru --output-dir <documents>
```

Или по существующей истории Git, без переключения checkout:

```powershell
python migration_documents.py --repository <repo> --range <base>..<head> --manifest-path packages/app/package.json --lock-path yarn.lock --lang ru --output-dir <documents>
```

При наличии независимых аудитов можно передать `--before-audit <report.json>` и `--after-audit <report.json>`. Команда не запускает аудит сама. В шапке явно указано, что отчёт реконструирован и прогона утилиты не было. Для отсутствующих аудит/lag/checks/proof используются пометки, а не придуманные результаты. Одинаковые входные артефакты и язык дают одинаковые байты документов; время генерации не добавляется.

Для независимого аудита точного checkout используйте параметры действующей политики из `python manual_dependency_audit.py --help`. Его Markdown также поддерживает явный `--lang en|ru`; JSON сохраняет прежний контракт.

## Проверки

`tests/regression/test_migration_document_languages.py` проверяет полноту каталогов, явный выбор языка, неизменность JSON/команд/хешей, отсутствие аудита C0, расхождения артефактов, реконструкцию по двум манифестам и Git, воспроизводимость и отсутствие ложного вывода «обновлений не было». Доставка русского набора проверяется через настоящий Git в `tests/regression/test_iterative_delivery.py`.
